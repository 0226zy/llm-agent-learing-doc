4.7 沙箱边界与演进：跨对话隔离不等于同容器管理面隔离

边界P0 约束验证/演进

5.3 Run 状态机与并发闸门

状态含义进入退出
queued等沙箱配额或启动消息已接收，闸门抢占成功沙箱就绪 → dispatching；明确尚未下发时取消/超时 → finalizing（记录未执行），再进入对应终态
dispatching执行接收确认中写入持久 Run、申请配额后下发 run_id；Runtime 先准备接收，不启动推理准备接收确认 → 控制层提交 running → 幂等 start；响应未知先按 run_id 查询；取消/超时进入 cancelling 并撤销未开始或停止已开始执行，不直接另建任务
running已授权执行，start 已发送或正在确认Runtime 已持久准备接收；控制层 running 先提交，之后幂等 start，确保首次 LLM 请求可获授权turn_done/turn_failed → finalizing；取消或超时 → cancelling；尚不释放活跃位
cancelling取消已受理、执行未确认停止用户取消或总时限到达确认进程树停止 → finalizing；无法确认则保留锁并停止整容器兜底
finalizing确认停止并形成 checkpointRuntime 终态与无旧写入者确认记录 checkpoint 完成或明确失败 → terminal；提交失败不得假装已生成 commit，也不得携旧写入者释放锁
finished / failed / cancelled产品终态停止确认及收尾结果已记录同事务写结果、终态事件与 Factive=NULL；提交后广播，再以代码快照请求预览

闸门：UNIQUE(Fconv_id,Factive) 仅保证活跃记录唯一（未结束为 1，结束置 NULL）。先按 client_request_id 查询幂等记录，再抢活跃位；同编号不同规范化内容返回冲突。Runtime 接受平台 run_id 并持久化执行状态，相同 run_id 不重复执行。两个事实源之间的崩溃窗口通过查询和恢复扫描对账，不能以唯一索引宣称执行「恰好一次」。

扩容边界：P0 单控制层＋启动恢复扫描，任务不依赖客户端 HTTP context 继续存活。多副本前启用 owner／lease_until／generation，generation 在对话执行域内单调递增，Runtime 拒绝旧 generation 的修改/取消；租约失效不直接解锁，必须确认旧执行已停，并补齐跨实例事件通知和配额协调。

5.4 Run 编排流程（伪代码）

// 设计伪代码；错误、配额回滚和生命周期由统一分支处理，不代表已实现。
Start(requestCtx, user, convID, requestID, content, model) {
    conv = GetOwned(user, convID)                 // 不接受客户端伪造身份
    inputHash = Hash(CanonicalInput(content, model))
    tx = Begin()
    existing = FindRequest(tx, convID, requestID)
    if existing != nil { return SameInputOrConflict(existing, inputHash) }
    run = InsertActiveRun(tx, conv, requestID, inputHash)  // 只有活跃记录唯一
    InsertUserMessage(tx, run, content)
    PersistEvent(tx, "run_accepted", run)
    Commit(tx)                                  // 消息/Run/接收事件同时可见
    NotifyAfterCommit(run)                      // 只是通知，Worker 以库为准
    return Accepted(run)                        // HTTP 202
}

Drive(serviceCtx, run) {
    sb = EnsureSandboxWithReservation(serviceCtx, run.ConvID)
    sid = EnsureSingleSession(sb, "/workspace/app", run.Model)
    AcquireWorkspaceExecutionGate(run)          // 含旧预览重建门控，不在 DB 长事务内等待
    state = PrepareOrQuery(sb, sid, run.ID, run.InputHash, run.Generation)
    // Runtime仅持久准备，不立即推理；未知响应查询同一个run_id
    CommitRunningAuthorization(run)             // 先提交，LLM代理才允许该Run调用
    StartOrQuery(sb, sid, run.ID, run.Generation) // 幂等start；未知响应查执行状态
    ConsumeOrderedEventsAndReconcile(serviceCtx, sb, sid, run)
    if CancelRequested(run) { StopAndConfirmExecution(sb, run) }
    else { ConfirmExecutionStopped(sb, run) }
    MarkFinalizing(run)
    checkpoint = CommitOrRecordFailure(sb, run)  // 若仍有写入者，保持活跃位并先隔离
    tx = Begin()
    StoreTerminalAndCheckpoint(tx, run, checkpoint)
    PersistEvent(tx, TerminalEvent(run))
    ReleaseActiveRun(tx, run)                    // Factive=NULL
    Commit(tx)
    ReleaseWorkspaceGateAndRunQuota(run)
    NotifyAfterCommit(run)
    PreviewSnapshot(checkpoint.Commit)          // 快照构建；否则重新排队抢工作区门控
}

5.6 Runtime 事件消费（至少一次接收＋事务去重）

source = (conv.RuntimeEpoch, conv.AgentSessionID)
cursor = LoadSourceCursor(source)              // 下一个源 seq，不同于 UI seq
for {
    stream = StreamWithCursor(source, cursor)  // SSE/HTTP 读取都设总字节和分页上限
    select {
    case ev = <-stream:
        if ev.IsEphemeralDelta() { PublishTemporary(ev); continue } // S5，无持久 seq
        if ev.Seq < cursor { continue }         // 已消费的持久源事件
        if ev.Seq > cursor { RefillGap(source, cursor); continue }
        tx = Begin()
        if !ev.IsProgress() {
            InsertSourceOnce(tx, source, ev.Seq, ev) // 唯一键：epoch/session/rt_seq
        }
        // progress 在源日志占 seq，但不入 t_event、不分配 UI seq；仅同事务推进游标
        AdvanceCursor(tx, source, ev.Seq + 1)
        Commit(tx)
        cursor = ev.Seq + 1
        PublishCommittedOrTemporary(ev)        // 提交后通知；通知失败由库补扫
        if ev.IsTurnEnd() { ReconcileAndFinalize(run); return }
    case <-reconcileTicker:
        water, state = GetSourceWatermarkAndRun(source, run.ID)
        if water >= cursor { RefillGap(source, cursor) } // 覆盖最后一条丢失而无后续事件
        if state.Terminal { ConfirmExecutionStoppedAndFinalize(run) }
    }
}

序号域与边界：Runtime 原始 seq、平台持久 seq、临时 delta 三者分开。原始日志保留时 epoch 不变；日志重建/更换才增 epoch。控制层暂停与断线后重放须满足原日志仍可用、追加有序、接收游标同事务等前提；本设计不宣称双日志和网络实现端到端恰好一次。

慢订阅处理：持久事件满缓冲时断开，续传从最后完整消费游标开始；临时状态允许丢，但完整文本/终态必须对账。首屏分页历史后再连接 SSE，也必须在服务端登记订阅后补扫交集。一个原始事件映射多个卡片时用 (seq,item_index/call_id) 去重，不能只按 seq 丢弃其余工具调用。

5.8 LLM 代理

环节设计
鉴权以 token_hash 查对话与 scope，校验有效期、是否已撤销、Run 正在 running 且模型/调用额度允许（queued/cancelling/terminal 拒绝）。此机制不区分同 UID 下的 Agent 和生成应用；共容器试点需限额审计，强隔离阶段使用受控执行身份/代理通道。
模型校验请求里的 model 必须在目录内且该用户可用；控制层映射到上游真实模型名与地址，并强制设置 max_tokens 上限
透传语义上游的 429 / 5xx 与 Retry-After 必须原样返回。dsh-go 的重试分类（openai.Retryable）依赖状态码；代理若把它们吞掉改写成 200 或 500，退避与熔断就失效
流式代理从第一天起支持 SSE 透传，S5 上线时无需改动
计量记录对话、Run、模型、prompt / completion token、耗时、状态码到 t_llm_usage；这是用量与成本的权威来源
供应商P0 只接 OpenAI 兼容的上游（模型目录里 protocol: openai）；其他协议在代理内做转换，属于 P1
限流每对话并发 4、每用户 QPS 上限（初值，待调）；超限返回 429 并带 Retry-After

5.9 预览代理

  1. 前端调用 GET /api/conversations/{cid}/preview，控制层返回 https://{preview_key}.preview.<预览域名>/__enter?t=<60 秒签名票据>。
  2. 预览监听（:8081）验证票据的对话、具体 Host、nonce 和过期时间，一次性消费；设置 Host-only 的 HttpOnly; Secure Cookie（跨站嵌入按需 SameSite=None），重定向清除 URL 票据。撤权/删除后拒绝后续访问。
  3. 之后的请求校验预览 Cookie → 受控 Host 映射到该对话 → 反代固定 IP:3000（不采纳用户指定上游）；剥离平台/预览管理凭证，不传给生成后端，产品自己的 Cookie 按明确白名单保留；WebSocket 同样授权并限制连接寿命。
  4. 沙箱为 stopped 时返回「正在唤醒」页（自动刷新），同时触发恢复。
  5. 预览使用与主站不同的可注册域名，主站 Cookie 不扩散至预览；iframe 按需求最小开放 sandbox 权限。第三方 Cookie 可能被浏览器阻止，SameSite=None 不保证可用，Web 必须提供「新窗口预览」备用入口。

10.2 容量口径与故障验收

内存需求 = 平台/数据库保留 + 操作系统保留
         + 在线沙箱数 × 空闲/预览常驻基线
         + 同时推理数 × 额外上下文/请求体峰值
         + 同时构建数 × 额外构建峰值

额外峰值以基线增量计算，避免重复计数；同时按CPU、磁盘、模型额度和连接/带宽取约束最小值，并保留恢复余量。撤回前版「16核32GB可跑20–30活跃沙箱」的未经容器验证估算。例：32GB、平台/系统预留8GB、每容器硬限2GB，不超卖的额度算例最多12个；这仍不是实测安全容量。

  • 测试矩阵：真实模型；1/2/4/8个同时构建；200/2000/10000条历史；冷启动和热启动分别测，不以日志合成吞吐替代全链路。
  • 故障矩阵：202响应丢失、数据库提交失败、SSE终态丢失、控制层/Runtime重启、cancel后旧命令继续、进程脱组、OOM、磁盘满、端口冲突和容器IP变化。
