1. 产品功能设计

1.1 定位

平台面向内部可信试点用户 [待确认 Q-13]：用户用自然语言描述需求，Agent 在独立工作区内生成可运行的 Web 应用原型（React 前端 + Go 后端 + SQLite），用户在浏览器内查看代码、在线试用，并通过多轮对话迭代修改。产出用于需求沟通与方案验证，不直接部署到生产环境。

1.2 角色

角色画像可用功能
原型作者产品、研发、业务人员；能描述需求，不要求会写代码登录、对话管理、生成与迭代、查看代码、预览、切换模型
平台管理员负责平台运维预配与停用账号、重置密码、查询用量与运行概况、调整配额与模型目录（P0 通过命令行与配置文件，不提供管理页面）

1.5 功能规格

1.5.1 账号

功能业务规则界面反馈异常

1.5.2 对话

功能业务规则界面反馈异常
F-CONV-01模型默认取目录中 default；对话数上限取 t_user.Fmax_conv（默认 20，只计未删除对话）；创建时生成 conv_id（12 位）与 preview_key创建后直接进入该对话，输入框获得焦点；空对话显示 3 条示例需求，点击填入输入框429「对话数已达上限（20），请删除不用的对话」
F-CONV-02按 last_active 倒序，每页 30；徽标：queued 灰「排队中」、running 蓝「执行中」、error 红「异常」、idle 不显示排队中或执行中的对话每 10 秒刷新一次列表状态加载失败显示重试
F-CONV-03标题去首尾空白后 1–128 字符行内编辑，回车保存，Esc 取消400 保持编辑态并提示
F-CONV-04逻辑删除；有活跃 Run 时先受理取消；容器立即删除，卷保留 7 天仅供运维恢复，不对用户承诺可恢复确认框文案「删除后对话记录与工作区不可恢复」；确认后列表立即移除失败恢复列表项并提示
F-CONV-05首个 Run 接收时，若标题为空，取首条消息去掉换行后的前 30 字列表标题随之更新—

1.5.3 生成与执行

功能业务规则界面反馈异常
F-RUN-01内容 1–20000 字符；前端为每次主动发送生成 ULID 作为 client_request_id，网络重试沿用同一编号；同一对话有活跃 Run 时禁止发送Enter 发送、Shift+Enter 换行；发送后乐观显示用户消息；活跃 Run 期间输入框禁用，发送按钮变为「取消」发送失败的消息标红并提供「重试」（同一编号）；409 RUN_IN_PROGRESS 提示并刷新状态
F-RUN-02持久事件按 UI seq 有序展示；临时事件（进度、增量文本、文件变化、预览状态）不保证送达状态条：排队中 / 执行中 / 取消中 / 收尾中；工具卡片默认折叠，标题为命令或文件路径，失败标红，bash 输出用终端样式；截断输出显示「已截断」SSE 断开自动重连并续传；重连期间状态条显示「连接中断，正在重连」
F-RUN-03queued 状态取消立即生效（不执行）；其余状态进入「取消中」，停止确认后进入终态；取消后的 checkpoint 仍会保存已产生的改动点击后按钮变为「取消中…」并禁用；终态卡片显示「已取消 · 已保存版本 abc1234」或「已取消 · 无改动」强制停止工作区时显示「执行未能正常停止，工作区已重启；本轮改动未单独形成版本」
F-RUN-04仅 failed / cancelled 的最近一个 Run 可重新执行；使用原消息内容与对话当前模型，新的 client_request_id；生成一条新的用户消息终态卡片上的「重新执行」按钮同 F-RUN-01
F-RUN-05每用户同时执行 2 个对话，排队 5 个；排队超过 10 分钟自动失败queued 状态显示「排队中，资源空闲后自动开始」429「排队任务已达上限，请稍后再试」；QUEUE_TIMEOUT 终态卡片
F-RUN-06摘要取自 run_finished 事件：改动文件（≤50）、commit 前 7 位、耗时、prompt + completion token「完成 · 改动 6 个文件 · 版本 abc1234 · 用时 3 分 12 秒 · 12.3 万 tokens」；文件名可点击打开checkpoint 失败时显示「改动未保存为版本」
F-RUN-07进入对话先加载最近 200 条事件，向上滚动按 before 分页加载更早事件；回放与实时使用同一渲染规则加载更早记录时顶部显示加载指示—
F-RUN-08增量文本只做展示；收到同 Run 的完整 text 后以完整文本替换打字机效果增量丢失不影响最终文本
