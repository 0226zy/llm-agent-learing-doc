1.2 系统不变量（任何实现都不得破坏）

编号不变量
I1隔离单元是「对话」：每对话一个容器、一个可写卷、一个 dsh-go 会话；同一用户的两个对话也不共享可写目录。
I2同一对话同一时刻最多一个活跃 Run（状态 queued / dispatching / running / cancelling / finalizing）。不同对话可并行。
I3活跃位（t_run.Factive）只在「执行停止已确认 + checkpoint 结果已记录 + 终态事务已提交」之后释放；不随 HTTP 连接退出、租约过期或响应未知而释放。
I4持久事件先事务提交，后广播；广播只是通知，浏览器补发以数据库为准。
I5真实模型 Key 只在控制层；沙箱内只有绑定沙箱实例、可吊销、有有效期的沙箱令牌。
I6所有产品接口按 owner 校验；资源不存在与不属于当前用户统一返回 404。
I7三个序号域分离：Runtime 源 seq（dsh-go 日志）、平台 UI seq（t_event.Fseq，按对话递增）、临时事件（无 seq，不续传）。
I8Run 以 run_id 幂等：重复下发返回原任务；响应未知时先按 run_id 查询，禁止换新 run_id 重发。
I9ctx 取消、turn_failed、/healthz 都不是「执行已停止」的证明；只有 Runtime 返回 stopped_confirmed=true 且 wsd 孤儿清理完成，或容器已确认退出，才算停止。
I10预览只展示已确认版本；generation 更小的预览请求不得替换当前预览。

4.2 S8 Run 契约（dshd 新增 API）

所有接口需 Authorization: Bearer {MAGENTS_AUTH_TOKEN}。旧接口 POST /v1/sessions/{id}/messages 与 /cancel 保留以兼容测试，但 wsd 不放行。

方法与路径请求行为与响应
POST /v1/sessions/{sid}/runs{run_id, content, model, payload_hash, generation}只持久化准备记录，不启动推理。状态 prepared。相同 run_id + 相同 hash → 200 返回原记录；相同 run_id + 不同 hash → 409 RUN_ID_CONFLICT；会话已有其它非终态 Run → 409 SESSION_BUSY；generation 小于会话已见最大值 → 409 STALE_GENERATION。新建返回 201。
POST /v1/sessions/{sid}/runs/{rid}/start—幂等：prepared → running 并启动回合，返回 202；已 running 或已结束则返回当前状态 200。
GET /v1/sessions/{sid}/runs/{rid}—返回 RunState；不存在 404。
POST /v1/sessions/{sid}/runs/{rid}/cancel—prepared → 直接 stopped（outcome=cancelled，从未执行）；running → cancelling，向本 Run 的执行树发 SIGTERM，5 秒后 SIGKILL，确认进程组为空后 stopped；已 stopped 返回当前状态。返回 202。
RunState {
  run_id            string
  status            "prepared" | "running" | "cancelling" | "stopped"
  outcome           "" | "done" | "failed" | "cancelled"     // status=stopped 时非空
  stopped_confirmed bool       // 本 Run 启动的全部进程组已确认为空
  epoch             string     // 会话日志 epoch
  seq_start         int        // 本 Run 第一条源事件 seq
  next_seq          int        // 会话日志下一个 seq（高水位，用于补扫）
  error_code        string
  iterations, prompt_tokens, completion_tokens int
  model             string
  created_at, started_at, stopped_at string   // RFC 3339
}

持久化：{data_dir}/sessions/{sid}/runs/{run_id}.json，写临时文件 → fsync → rename。执行树：Run 内创建的 bash shell（含 task 子代理）使用 Setpgid 独立进程组，记录 pgid 列表到 Run 记录；取消或回合结束时关闭这些 shell，下一个 Run 新建 shell。重启恢复：dshd 启动时，对 status 为 running / cancelling 的记录逐个检查 pgid（kill(-pgid,0)），存活则 SIGKILL，确认为空后置 stopped（outcome=failed，error_code=RUNTIME_RESTARTED）。

marker 归属：turn_done / turn_failed 在 S2 中带 run_id；marker 写入只表示回合逻辑结束，不代表 stopped_confirmed。

5.8 预览守护

  1. 模式：P0 只实现 live 模式（在 /workspace/app 原地构建，构建期间持有工作区门控）。snapshot 模式（按 commit 导出到独立目录构建，可与下一个 Run 并行）作为 M5 可选项，配置 preview.mode 预留。[待确认 Q-05]
  2. 版本序：wsd 记录当前预览 {generation, commit}。请求 generation 小于当前值 → 409 STALE_GENERATION；相同 generation 且 ready → 直接返回。
  3. 门控：请求头 X-Run-Id 与门控持有者一致（S4 在 Run 内调用）→ 复用，不再申请；否则以 holder:"preview" 申请门控，构建结束（探活成功或失败）即释放。
  4. 构建名额：构建前调用控制层 POST /internal/build/acquire；返回 429 时按 Retry-After 等待，总等待计入 wait；探活结束后 /internal/build/release。
  5. 启动：停止旧预览进程组（SIGTERM → 5 秒 → SIGKILL）；检查 3000 端口，若被非登记进程占用 → failed，PORT_CONFLICT（不杀未知进程）；以独立进程组执行 bash /workspace/app/start.sh，环境 {PATH, HOME, LANG, PORT=3000, DATA_DIR=/workspace/appdata, GOPROXY, GOFLAGS, GOMODCACHE, npm_config_registry, npm_config_cache}，不含任何令牌。
  6. 探活：每秒 GET http://127.0.0.1:3000/，返回 200 即 ready；401/404 不算可用；超时 90 秒 → failed。
  7. 守护：ready 后进程退出则重启，最多 3 次；日志环形缓冲 2000 行 / 1 MB。

6.7 Runtime 源事件消费（至少一次接收 + 事务去重）

Consume(ctx, run):
    src := (conv.Fruntime_epoch, conv.Fagent_session_id)
    cursor := conv.Frt_next_seq                           // 下一个期望的源 seq
    ticker := every(reconcile_interval)                   // 默认 5s
    loop:
        stream := wsd.Stream(sid, from_seq=cursor)        // 断开 → 指数退避重连，从 cursor 续读
        select:
        case ev := <-stream:
            if ev.IsDelta():    hub.PublishTemp(conv, Map(ev)); continue      // S5，无 seq
            if ev.seq < cursor: continue
            if ev.seq > cursor: Refill(src, cursor, ev.seq-1)                // GET events?from_seq=cursor 分页补齐
            WithTx:
                if !ev.IsProgress():
                    InsertSourceOnce(conv, src, ev)       // uk_source_event 冲突即视为已消费；分配 UI seq
                conv.Frt_next_seq = ev.seq + 1            // progress 也推进游标
            cursor = ev.seq + 1
            ev.IsProgress() ? hub.PublishTemp(conv, Map(ev)) : hub.Notify(conv)
            if ev.IsTurnMarker() && ev.run_id == run.id: return OutcomeOf(ev)
        case <-ticker:
            st := dsh.GetRun(sid, run.id)
            if st.next_seq > cursor: Refill(src, cursor, st.next_seq-1)   // 覆盖「最后一条丢失且无后续事件」
            if st.status == stopped && cursor >= st.next_seq: return st.outcome
        case <-ctx.Done() / cancelSignal: return cancelled

Refill 内对每条事件执行与上面相同的事务逻辑。日志 epoch 变化（日志重建）时 cursor 归零并更新 Fruntime_epoch，旧 epoch 事件保留。不宣称端到端恰好一次。

6.8 事件模型与浏览器 SSE

帧结构：一条 t_event 对应一条 SSE 消息，避免「一个原始事件映射多张卡片」在断线时丢失部分卡片。

id: {seq}                       // 临时事件不带 id
event: ui
data: {"seq":123, "run_id":"01J…", "ts":"2026-10-24T10:00:00Z",
       "items":[{"key":"call_abc","type":"tool_call","data":{…}}, …]}

SSE 端点算法：① owner 校验；② 先在 Hub 登记订阅；③ 从 after（或 Last-Event-ID）起按 Fseq 分页读库发送，直至当前高水位；④ 之后收到 Notify 时再从「最后已发送 seq」读库续发——Notify 只是提示，内容一律读库，天然去重；⑤ 临时事件直接写出，写出阻塞超过 100 ms 则丢弃临时事件；⑥ 每 15 秒心跳 : ping，同时检查库中高水位；⑦ 单次写出超时 30 秒则断开，客户端重连续传。

UI seq 分配：在事件事务内 SELECT Flast_seq FROM t_conversation WHERE Fconv_id=? FOR UPDATE，+1 后写入 t_event 与 t_conversation。

6.13 预览代理

  1. GET /api/conversations/{cid}/preview 返回 https://{preview_key}.preview.<预览域名>/__enter?t={票据}。preview_key 为对话创建时生成的 128 位随机值（base32，26 字符），不使用 conv_id。
  2. 票据：HMAC 签名，载荷 {conv_id, host, nonce, exp=60s}；nonce 一次性消费（P0 内存保存，重启后全部失效）。
  3. :8081 收到 /__enter：验证票据与 Host → 设置 Host-only 的 HttpOnly; Secure Cookie（值为无状态 HMAC 签名 {conv_id, host, exp=12h}，控制层重启不失效）（iframe 场景 SameSite=None）→ 302 到 / 清除票据。/__enter 为平台保留路径。
  4. 后续请求：校验预览 Cookie → Host 映射到对话 → 反代固定 {容器 IP}:3000（不接受用户指定上游）；剥离平台预览 Cookie，其余 Cookie 透传；WebSocket 同样授权，连接寿命上限 1 小时。
  5. 沙箱 stopped：返回「正在唤醒」页（5 秒自动刷新），同时触发 Ensure。对话删除或撤权后拒绝访问。
  6. 第三方 Cookie 可能被浏览器阻止，Web 必须提供「新窗口预览」入口。

6.14 控制层重启恢复

  1. 扫描 Factive=1 的 Run（queued / dispatching / running / cancelling / finalizing）。
  2. queued：重新入队。其余：按相同 run_id 调 GET /agent/sessions/{sid}/runs/{rid}，校验 epoch；从 Frt_next_seq 继续消费并补扫到高水位；按状态继续 Drive 后半段。
  3. Runtime 无该 run_id 记录且状态为 dispatching → 视为未下发，重新 prepare。沙箱不可达 → 走沙箱 error 流程。
  4. checkpoint 按 run_id 幂等，可重复调用。禁止以「租约过期」或「响应未知」释放活跃位。
